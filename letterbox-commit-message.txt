Close the letterbox gap: export the detector with dynamic H/W

The README described this as a known difference that "has not been done".
It is done.

The detector was exported with dynamic=False, freezing the ONNX input at
640x640, so every photo had to be padded out to a full square while
Ultralytics pads only to the next multiple of 32. Same weights, different
framing, slightly different boxes - and on a borderline crop, a different
verdict.

- export_onnx.py: dynamic=True.
- obb_postprocess.py: letterbox() gains AUTO_PAD, padding to a stride
  multiple rather than a square. Set it False to reproduce the old
  behaviour.
- postprocess() needed no change: it already read the candidate count off
  the tensor instead of assuming 8400, so 5880 anchors work unmodified.

Measured by verify_obb.py over 20 photos held out from the source dataset,
against PyTorch + Ultralytics:

                              before      after
  mean polygon IoU            0.98333     1.00000
  worst polygon IoU           0.94319     1.00000
  worst confidence delta      0.02270     0.00000
  median detect()             140.5 ms    63.6 ms

The geometry difference is gone rather than reduced. The speedup was not
the goal: a 1024x1536 photo now enters at 640x448, 30% fewer pixels and
5880 candidates instead of 8400. Padding less is faster than padding more.

Also fixed, because they were broken in this standalone repo: six scripts
still looked for the PyTorch checkpoints one directory up, the layout of
the original course repo. They now use weights/, overridable via
DETECTOR_PT and CLASSIFIER_PT, matching export_onnx.py.

Still unverified: invalid_01.png from the original demo set. Crop geometry
was the only remaining difference and is now identical, so the cause is
removed - but that image has not been re-run.
